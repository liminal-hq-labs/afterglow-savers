# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Status is **Owner** when the owner decided it and **Assumed** when work proceeds on a recommended default until confirmed.

| # | Decision | Choice | Status | Why |
| --- | --- | --- | --- | --- |
| SAV-D1 | Savers and file names | Four savers (Maze, Cracktro, Twilight, Ink) and a Collection, named "Afterglow <Name>" by string 1; files in 8.3 form with no spaces: `AGMAZE.SCR`, `AGCRACK.SCR`, `AGTWILIT.SCR`, `AGINK.SCR`, `AGCOLLCT.SCR` | Owner (names), Assumed (files) | The Display applet runs `"<path> /p <hwnd>"` without quotes, and Windows 9x stores short names; 8.3 names work everywhere. |
| SAV-D2 | Rendering | A CPU software renderer drawing into a 32-bit DIB, shown with `StretchDIBits`; no OpenGL or Direct3D | Owner | ReactOS's OpenGL is poor, and a software renderer looks the same everywhere. |
| SAV-D3 | Memory | `savers-core` is `no_std` with `alloc`; the Win32 shell's global allocator is the process heap (`HeapAlloc`) | Assumed | Frame buffers and textures depend on the screen size; a heap keeps the scenes simple, and the process heap needs no C runtime. |
| SAV-D4 | Pentium floats | The i586 target uses the x87 FPU (the default 32-bit ABI) with MMX and SSE off; afterfetch's soft-float target is not used. x86-64 uses its SSE2 baseline | Assumed | A renderer is float-heavy outside its inner loops; soft-float would cost ten times more, and every Pentium has an FPU. |
| SAV-D5 | Maths | The core's own `sin`, `cos`, `sqrt`, `exp`, `pow` and value noise, deterministic, with a magic-number float-to-integer conversion; inner loops are 16.16 fixed point | Owner (no libm), Assumed (method) | No libm in `no_std`; x87 `fistp` with Rust's saturating casts is slow, and fixed point is fast on every target. |
| SAV-D6 | Determinism | The same seed, settings, size and time give the same frame on one build; the golden frame tests run on the host build only, because x87's extended precision may round a value differently | Assumed | Exact cross-FPU agreement would forbid floats; one-build determinism is what tests and previews need. |
| SAV-D7 | Settings key | `HKCU\Software\Liminal HQ\Afterglow Screensavers\<Name>`, `REG_DWORD` and `REG_SZ` values through the ANSI registry calls | Owner (place), Assumed (values) | Per-user, like the stock savers, under the house's own key. |
| SAV-D8 | Collection settings | The Collection's own common settings (quality, palette, finish) apply to every scene it plays; each scene's own scene settings and seed come from that scene's key | Assumed | One quality choice for the collection, while the per-scene tuning is not repeated. |
| SAV-D9 | Resources and dialog | Each `.res` (string table, icon, version) is written by a deterministic host build script and linked by `lld-link`; the settings dialog is a `DLGTEMPLATE` built in memory | Assumed | No resource compiler or C toolchain is needed, and the dialog layout lives in Rust beside the settings it edits. |
| SAV-D10 | Exit rules | Those of ReactOS's `scrnsave.lib`: keys, buttons and deactivation end it; mouse moves after 10 pixels from the first position | Owner | Users expect the stock behaviour. See `docs/reactos-scr.md`. |
| SAV-D11 | Preview | Drawn at the preview window's own size, Low detail, 20 frames a second at most, ends when its parent goes | Assumed | The preview sits beside a dialog in use and must cost almost nothing. |
| SAV-D12 | Burn-in rule | Nothing bright holds still for more than 8 seconds, mostly-dark frames, grain keeps every pixel moving, no parked overlays | Owner (intent), Assumed (numbers) | The XP-era purpose of a screensaver, kept as a testable rule. |
| SAV-D13 | Landing | Local repository with no remote; straight onto `main` after `make check`; parallel builders in worktrees, fast-forwarded | Owner | As afterfetch (AF-D11). |
| SAV-D14 | Budgets | Each `.scr` at most 192 KiB; the five main files together at most 640 KiB | Owner | Small enough for a floppy-era system folder. |
| SAV-D15 | Text | An original stroke font in the core, drawn anti-aliased at any size at startup; no bitmap font or GDI text in a scene | Assumed | The scroller needs big smooth letters in every resolution, and the core must be host-testable. |
| SAV-D16 | Textures | Every texture, the planet and the maze are generated at startup from a seed | Owner | No big embedded bitmaps; a new look every run. |
| SAV-D17 | Passwords | No Windows 9x password support; NT and ReactOS lock through Winlogon | Assumed | ReactOS's own `scrnsave.lib` has none, and the target is ReactOS. |
| SAV-D18 | Previews | `savers-preview` writes PNG frames with its own encoder; GIF and MP4 are made from them with `ffmpeg` | Assumed | No crates needed on the host; `ffmpeg` and ImageMagick are installed. |
| SAV-D19 | Frame-rate targets | 25% and Low at least 15 frames a second on a Pentium III-class machine; 100% and Ultra at least 30 on a modern virtual machine; estimates from a calibrated reference loop | Owner | The owner's floor and ceiling. |
| SAV-D20 | Quill Ghostwriter | An Easter-egg sixth saver, `AGQUILL.SCR`, "Quill Ghostwriter", built after the others; never installed or selected by default, in no default list, in the Collection only by opting in; its own 192 KiB budget outside the five's 640 KiB | Owner | A nerdy text saver for Quill, to be discovered, perhaps started from Quill's About box later. |
| SAV-D21 | Quill's look | Quill's colours (navy `#0a1230` and `#14142a`, gold `#f0a830`, cream `#fbf7ea`) and its window layout (title bar, menu, B/I/U toolbar, ruler with gold tab stops, cream page, status bar) are followed. Quill's `QUILL.FNT` strikes are rendered from OFL and Liberation-licensed TrueType fonts, so they are **not** copied: the eras are drawn with the core's own stroke font three ways (pixel-snapped 8 × 16 cells for DOS, hard-edged for Windows 3.x, anti-aliased for modern) | Owner (look), Assumed (fonts) | Copying the strikes would add two font licences to an `Apache-2.0 OR MIT` program for a few kilobytes of glyphs. |
| SAV-D22 | Where Quill Ghostwriter ships | A real `.scr` that appears in the Screen Saver list as "Quill Ghostwriter" wherever it is installed, never selected by default and not in the Collection by default. It ships **only** with the Quill remix of the ReactOS image (an extra `[[files]]` entry in Quill's recipe) and as an optional, unselected component of Quill's own installers (a Win32 `.scr` runs natively on Windows 95, 98, Me and NT); **not** in the Afterglow base, full or compact recipes. Its crate and file stay separate, so Quill's installers can ship it alone | Owner (not objected) | It is Quill's Easter egg: found by poking through the settings on a Quill system, and absent where Quill is not. |
| SAV-D23 | Quill Ghostwriter for Windows 3.x | A Win16 edition, `QUILLGW.SCR` (an NE executable, listed as "Quill Ghostwriter"), built with the vendored rust-win16 packer as Quill's Win16 build is: a reduced scene for 16-bit GDI at 640 × 480 in 16 colours (256 where the driver allows): the window drifting, typing with a typo, the squiggle, the suggestion and the correction, the status bar, and the "Save the changes?" visit, with a small embedded text bank and settings in `CONTROL.INI`. Built after the Win32 Ghostwriter. If ReactOS's Display applet cannot start a Win16 `.SCR` (its 16-bit hand-off may lose the command line), this edition is labelled "Windows 3.x edition" for real Windows 3.x and is not placed in ReactOS's `system32` | Owner | Windows 3.1 had screensavers too, and Quill has a Windows 3.x build. |
| SAV-D24 | Ghostwriter in Quill's installers | Quill's Windows 95 installer offers both editions as optional components, unselected by default (the Win32 `.scr` into `%WINDIR%\SYSTEM`, `QUILLGW.SCR` into the Windows directory); the Windows 3.x installer offers the 16-bit one only. Wiring is described in `docs/quill-installer-integration.md`; this repository does not edit Quill or the installer | Owner | Someone with the Windows 95 build can play with the old-school and the new-school saver. |
| SAV-D25 | Twilight on the graphics card | A wgpu edition of Twilight for 4K in real time, first on Linux: a host-only `std` area (`crates/savers-gpu`, `platforms/linux`) that shares the camera, the seeded parameters, the map painters, the ramps and the settings with the CPU scene, which stays the reference and is held to it by a parity test (headless through lavapipe). A fullscreen winit binary and an xscreensaver hack. Never linked into a `.scr`. Design in `docs/gpu-twilight.md`; after Cracktro, Maze and the Win32 shells | Owner | "Graphics card version, please!" Twilight is a pure function of time, so it ports without a simulation to keep in step. |
| SAV-D26 | An Afterglow settings dialog | A second edition of the `/c` dialog: a banner that is the saver's own scene rendered once, clickable palette swatches (owner-drawn buttons that stay real, focusable, named controls), a live preview pane running the real scene at Low detail, Afterglow rules and labels over the system's colours and font; the plain dialog stays as the fallback for high contrast and 256-colour screens. After the plain dialogs land. Design in `docs/settings-dialog.md` | Owner | "Afterglowify" the settings boxes, without losing keyboard use or readability on Windows 95 and ReactOS. |
| SAV-D27 | Twilight's sun | Shown by default, with a "Show the sun" setting (`Sun`): a small white-hot disc with a glow, far off on the lit side in the establishing shot, and sliding out from behind the limb in the night-side drift, which is lit from behind; never set on a horizon, so it is not a sunset | Owner | The owner wants the sun, without a sunset as such. |
| SAV-D28 | Twilight's shared module | Twilight's camera and shot table, seeded parameters (moons, satellites, stars, spin), map painters, map sizes and colour ramps live in `savers_core::twilight_shared` (`Shared`, `camera`, `map_size`, the `paint_*` functions), public and pure, so the graphics-card edition draws from the same data as the CPU scene, which reads it through the module. No behaviour change: the goldens did not move. `Shared::with_map_size` lets a graphics card ask for 2048 × 1024 at any detail level | Assumed | SAV-D25 needs one source for the planet; the CPU scene stays the reference. |
