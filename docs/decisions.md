# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Status is **Owner** when the owner decided it and **Assumed** when work proceeds on a recommended default until confirmed.

| # | Decision | Choice | Status | Why |
| --- | --- | --- | --- | --- |
| SAV-D1 | Savers and file names | Four savers (Maze, Cracktro, Twilight, Ink) and a Collection, named "Afterglow <Name>" by string 1; files in 8.3 form with no spaces: `AGMAZE.SCR`, `AGCRACK.SCR`, `AGTWILIT.SCR`, `AGINK.SCR`, `AGCOLLCT.SCR` | Owner (names), Assumed (files) | The Display applet runs `"<path> /p <hwnd>"` without quotes, and Windows 9x stores short names; 8.3 names work everywhere. |
| SAV-D2 | Rendering | A CPU software renderer drawing into a 32-bit DIB, shown with `StretchDIBits`; no OpenGL or Direct3D | Owner | ReactOS's OpenGL is poor, and a software renderer looks the same everywhere. |
| SAV-D3 | Memory | `savers-core` is `no_std` with `alloc`; the Win32 shell's global allocator is the process heap (`HeapAlloc`) | Assumed | Frame buffers and textures depend on the screen size; a heap keeps the scenes simple, and the process heap needs no C runtime. |
| SAV-D4 | Pentium floats | The i586 target uses the x87 FPU (the default 32-bit ABI) with MMX and SSE off; afterfetch's soft-float target is not used. x86-64 uses its SSE2 baseline | Assumed | A renderer is float-heavy outside its inner loops; soft-float would cost ten times more, and every Pentium has an FPU. |
| SAV-D5 | Maths | The core's own `sin`, `cos`, `sqrt`, `exp`, `pow` and value noise, deterministic, with a magic-number float-to-integer conversion; inner loops are 16.16 fixed point | Owner (no libm), Assumed (method) | No libm in `no_std`; x87 `fistp` with Rust's saturating casts is slow, and fixed point is fast on every target. |
| SAV-D6 | Determinism | The same seed, settings, size and time give the same frame on one build; the golden frame tests run on the host build only, because x87's extended precision may round a value differently | Assumed | Exact cross-FPU agreement would forbid floats; one-build determinism is what tests and previews need. |
| SAV-D7 | Settings key | `HKCU\Software\Liminal HQ\Afterglow Screensavers\<Name>`, `REG_DWORD` and `REG_SZ` values through the ANSI registry calls | Owner (place), Assumed (values) | Per-user, like the stock savers, under the house's own key. |
| SAV-D8 | Collection settings | The Collection's own common settings (quality, palette, finish) apply to every scene it plays; each scene's own scene settings and seed come from that scene's key | Assumed | One quality choice for the collection, while the per-scene tuning is not repeated. |
| SAV-D9 | Resources and dialog | Each `.res` (string table, icon, version) is written by a deterministic host build script and linked by `lld-link`; the settings dialog is a `DLGTEMPLATE` built in memory | Assumed | No resource compiler or C toolchain is needed, and the dialog layout lives in Rust beside the settings it edits. |
| SAV-D10 | Exit rules | Those of ReactOS's `scrnsave.lib`: keys, buttons and deactivation end it; mouse moves after 10 pixels from the first position | Owner | Users expect the stock behaviour. See `docs/reactos-scr.md`. |
| SAV-D11 | Preview | Drawn at the preview window's own size, Low detail, 20 frames a second at most, ends when its parent goes | Assumed | The preview sits beside a dialog in use and must cost almost nothing. |
| SAV-D12 | Burn-in rule | Nothing bright holds still for more than 8 seconds, mostly-dark frames, grain keeps every pixel moving, no parked overlays | Owner (intent), Assumed (numbers) | The XP-era purpose of a screensaver, kept as a testable rule. |
| SAV-D13 | Landing | Local repository with no remote; straight onto `main` after `make check`; parallel builders in worktrees, fast-forwarded | Owner | As afterfetch (AF-D11). |
| SAV-D14 | Budgets | Each `.scr` at most 192 KiB; the five main files together at most 640 KiB. **Superseded by SAV-D29** (384 KiB and 1.5 MiB, as a guard) | Owner | Small enough for a floppy-era system folder. |
| SAV-D15 | Text | An original stroke font in the core, drawn anti-aliased at any size at startup; no bitmap font or GDI text in a scene | Assumed | The scroller needs big smooth letters in every resolution, and the core must be host-testable. |
| SAV-D16 | Textures | Every texture, the planet and the maze are generated at startup from a seed | Owner | No big embedded bitmaps; a new look every run. |
| SAV-D17 | Passwords | No Windows 9x password support; NT and ReactOS lock through Winlogon | Assumed | ReactOS's own `scrnsave.lib` has none, and the target is ReactOS. |
| SAV-D18 | Previews | `savers-preview` writes PNG frames with its own encoder; GIF and MP4 are made from them with `ffmpeg` | Assumed | No crates needed on the host; `ffmpeg` and ImageMagick are installed. |
| SAV-D19 | Frame-rate targets | 25% and Low at least 15 frames a second on a Pentium III-class machine; 100% and Ultra at least 30 on a modern virtual machine; estimates from a calibrated reference loop | Owner | The owner's floor and ceiling. |
| SAV-D20 | Quill Ghostwriter | An Easter-egg sixth saver, `AGQUILL.SCR`, "Quill Ghostwriter", built after the others; never installed or selected by default, in no default list, in the Collection only by opting in; its own 192 KiB budget outside the five's 640 KiB | Owner | A nerdy text saver for Quill, to be discovered, perhaps started from Quill's About box later. |
| SAV-D21 | Quill's look | Quill's colours (navy `#0a1230` and `#14142a`, gold `#f0a830`, cream `#fbf7ea`) and its window layout (title bar, menu, B/I/U toolbar, ruler with gold tab stops, cream page, status bar) are followed. Quill's `QUILL.FNT` strikes are rendered from OFL and Liberation-licensed TrueType fonts, so they are **not** copied: the eras are drawn with the core's own stroke font three ways (pixel-snapped 8 × 16 cells for DOS, hard-edged for Windows 3.x, anti-aliased for modern) | Owner (look), Assumed (fonts) | Copying the strikes would add two font licences to an `Apache-2.0 OR MIT` program for a few kilobytes of glyphs. |
| SAV-D22 | Where Quill Ghostwriter ships | A real `.scr` that appears in the Screen Saver list as "Quill Ghostwriter" wherever it is installed, never selected by default and not in the Collection by default. It ships **only** with the Quill remix of the ReactOS image (an extra `[[files]]` entry in Quill's recipe) and as an optional, unselected component of Quill's own installers (a Win32 `.scr` runs natively on Windows 95, 98, Me and NT); **not** in the Afterglow base, full or compact recipes. Its crate and file stay separate, so Quill's installers can ship it alone | Owner (not objected) | It is Quill's Easter egg: found by poking through the settings on a Quill system, and absent where Quill is not. |
| SAV-D23 | Quill Ghostwriter for Windows 3.x | A Win16 edition, `QUILLGW.SCR` (an NE executable, listed as "Quill Ghostwriter"), built with the vendored rust-win16 packer as Quill's Win16 build is: a reduced scene for 16-bit GDI at 640 × 480 in 16 colours (256 where the driver allows): the window drifting, typing with a typo, the squiggle, the suggestion and the correction, the status bar, and the "Save the changes?" visit, with a small embedded text bank and settings in `CONTROL.INI`. Built after the Win32 Ghostwriter. If ReactOS's Display applet cannot start a Win16 `.SCR` (its 16-bit hand-off may lose the command line), this edition is labelled "Windows 3.x edition" for real Windows 3.x and is not placed in ReactOS's `system32` | Owner | Windows 3.1 had screensavers too, and Quill has a Windows 3.x build. |
| SAV-D24 | Ghostwriter in Quill's installers | Quill's Windows 95 installer offers both editions as optional components, unselected by default (the Win32 `.scr` into `%WINDIR%\SYSTEM`, `QUILLGW.SCR` into the Windows directory); the Windows 3.x installer offers the 16-bit one only. Wiring is described in `docs/quill-installer-integration.md`; this repository does not edit Quill or the installer | Owner | Someone with the Windows 95 build can play with the old-school and the new-school saver. |
| SAV-D25 | Twilight on the graphics card | A wgpu edition of Twilight for 4K in real time, first on Linux: a host-only `std` area (`crates/savers-gpu`, `platforms/linux`) that shares the camera, the seeded parameters, the map painters, the ramps and the settings with the CPU scene, which stays the reference and is held to it by a parity test (headless through lavapipe). A fullscreen winit binary and an xscreensaver hack. Never linked into a `.scr`. Design in `docs/gpu-twilight.md`; after Cracktro, Maze and the Win32 shells | Owner | "Graphics card version, please!" Twilight is a pure function of time, so it ports without a simulation to keep in step. |
| SAV-D26 | An Afterglow settings dialog | A second edition of the `/c` dialog: a banner that is the saver's own scene rendered once, clickable palette swatches (owner-drawn buttons that stay real, focusable, named controls), a live preview pane running the real scene at Low detail, Afterglow rules and labels over the system's colours and font; the plain dialog stays as the fallback for high contrast and 256-colour screens. After the plain dialogs land. Design in `docs/settings-dialog.md` | Owner | "Afterglowify" the settings boxes, without losing keyboard use or readability on Windows 95 and ReactOS. |
| SAV-D27 | Twilight's sun | Shown by default, with a "Show the sun" setting (`Sun`): a small white-hot disc with a glow, far off on the lit side in the establishing shot, and sliding out from behind the limb in the night-side drift, which is lit from behind; never set on a horizon, so it is not a sunset | Owner | The owner wants the sun, without a sunset as such. |
| SAV-D28 | Twilight's shared module | Twilight's camera and shot table, seeded parameters (moons, satellites, stars, spin), map painters, map sizes and colour ramps live in `savers_core::twilight_shared` (`Shared`, `camera`, `map_size`, the `paint_*` functions), public and pure, so the graphics-card edition draws from the same data as the CPU scene, which reads it through the module. No behaviour change: the goldens did not move. `Shared::with_map_size` lets a graphics card ask for 2048 × 1024 at any detail level | Assumed | SAV-D25 needs one source for the planet; the CPU scene stays the reference. |
| SAV-D29 | Win32 build size | **Revised.** The `.scr` files are built for speed, `opt-level = 3` (as the host build the frame times come from; Ink at 100% Ultra is about 25% faster than at `2`, the others even), and the size budgets of SAV-D14 become a guard against accidents: 384 KiB per file and 1.5 MiB for the five main files. The Collection links all five scenes again; Quill Ghostwriter stays out by default (the `Savers` mask) and, when asked for, plays only if `AGQUILL.SCR` is installed beside `AGCOLLCT.SCR` (otherwise that turn is Ink's), so it stays absent on a system without Quill. First recorded as `opt-level = "s"` with Ghostwriter left out, to fit 192 KiB | Owner | File size is not a constraint for the Win32 savers; frame rate is. |
| SAV-D30 | Losing activation | A window that has never been active does not end the saver on a deactivation; once it has been active, losing activation ends it as `scrnsave.lib` does | Assumed | Wine without a window manager sends a deactivation while the window is still being shown after another saver's window has gone; the saver has not lost anything it had. |
| SAV-D31 | The Maze's portal | The exit is a portal of stepped dusk light; through it shows the next walk's opening pose, rendered live; the camera approaches, eases back, holds about 1.5 s, then slowly passes through, and the walk carries on from the beginning with no cut, flash or fade. The saver walks a new maze each time (`LoopMaze` off, the default; a new seed each run); with `LoopMaze` on, and for video renders, it is the same maze, a true loop: frame(t) equals frame(t + one walk), held by a test that also bounds the crossing's change to an ordinary step | Owner | A long-running saver or a looped video shows no seam; the swap to a new maze happens behind the aperture. |
| SAV-D32 | The graphics-card renderer's dependencies | `crates/savers-gpu` (host only, `std`) depends on `wgpu` 30.0.1 (default features off: `std`, `parking_lot`, `vulkan`, `gles`, `metal`, `dx12`, `wgsl`; the browser path is never built), `pollster` 0.4 and `bytemuck` 1.25, and through wgpu on about 120 packages in the lockfile (many only for other platforms), every one under `MIT OR Apache-2.0` or a permissive licence named in `deny.toml`'s `exceptions`: ISC for `libloading`, Zlib for `foldhash` and `slotmap`, Unicode-3.0 for `unicode-ident`'s data (plus `zerocopy`'s BSD-2-Clause alternative, an `OR`). `make deny` (in `make check`) runs `cargo deny check licenses bans sources`. `savers-core` stays dependency-free and `no_std`; `winit` and the rest wait for WP-gpu-linux | Assumed | SAV-D25 budgets the dependencies; the exceptions are per crate, so nothing else gains the licences. The advisory database needs the network and is not in the gate. |
| SAV-D33 | The graphics-card edition's parity | The GPU edition is held to the CPU frames at 160 × 90 (seed 7, all four detail levels, one time in each shot, two more palettes with moons): at most 6 levels of mean absolute error per channel and 2% of pixels more than 24 levels apart, grain off; the finish alone on a synthetic frame in the same budget. Headless on lavapipe by default (`AFTERGLOW_GPU_ADAPTER` chooses another), skipping with a note when no adapter exists; the tests are part of `make check`. Moons' craters are the core's `noise3` baked to a texture, and the CPU's star arms (which copy the centre's colour) are matched, so the CPU scene stays the single source of the look | Assumed | The doc's own budget; the measured error is under half of it, and what is left is the CPU's fixed-point rounding. |
| SAV-D34 | Generative audio | Sound is synthesized in `savers-core` (oscillator tables, filters, FM bells, noise, a feedback-delay reverb, a soft limiter), no sample files, deterministic from the seed and the sample clock, following each scene's own timeline (Twilight's shots and sun, the Maze's walk and portal); Twilight vast and slow, the Maze an ambience with a rising tone and a whoosh at the portal, small scores for the others. Design in `docs/audio.md` | Owner (intent), Assumed (design) | Reproducible audio for videos without re-rendering pictures, and no sample licences or size. |
| SAV-D35 | Sound at run time | `waveOut` from `winmm.dll` in the frame loop, 22,050 Hz stereo, three 300 ms buffers; silent in `/p` and `/c` and when no device opens; soft fades with the picture, no loud events. `Sound` and `Volume` settings: **`Sound` on by default at `Volume` 28**, with the check box and slider at the top of the Look group and a line saying it plays quietly, so it is one click to turn off; the same defaults for the Collection and Ghostwriter (whose key ticks are quiet) | Owner | The owner wants the scores heard, at a level that does not startle; first recommended off, for unannounced sound at idle desks. |
| SAV-D36 | Audio for the videos | Rendered alone to WAV by `savers-preview audio` (looping cleanly with `--loop`), encoded to AAC 256 kbps and remuxed with `-c:v copy` onto the existing videos as new `*-audio.mp4` files; the silent files are kept | Owner | The 4K video took 12.5 minutes to render; the sound must not cost that again. |
| SAV-D37 | The Windows 3.x edition after the spike | `QUILLGW.SCR` builds (16 560 bytes; one code segment of 13 392; data, stack and heap 14 252 of 65 536) from Quill's Win16 toolchain, copied with provenance into its own workspace `platforms/win16`, and runs on Windows 3.11 (64K-colour and 16-colour VGA, in DOSBox-X) and under Wine. Windows 3.11 lists it by its `SCRNSAVE : Quill Ghostwriter` description, passes `/c` for Setup and `/s` for Test and the idle timer, and keeps the choice in `SYSTEM.INI` `[boot]` `SCRNSAVE.EXE=` and `WIN.INI`; settings are `Acts` and `Speed` in `CONTROL.INI`. **Go** for the Windows 3.x editions of Quill's installers (SAV-D24). **Not placed in ReactOS's `system32`**: the Display applet lists a 16-bit file as "Unknown" and ReactOS's NTVDM fails when the applet starts it; otvdm was not shown to run it. SAV-D23's fallback applies | Assumed | The spike answered SAV-D23's open question. Findings and screendumps are in `docs/win16-ghostwriter.md` |
| SAV-D38 | Audio fidelity | Offline renders and the Linux GPU edition at 48 kHz stereo with `f32` synthesis (FLAC masters beside the videos, AAC 256 kbps in the MP4s); the Win32 savers on a ladder by Detail: Low 22,050 Hz, Medium 32,000, High 44,100, Ultra 48,000 | Owner | Full fidelity wherever the CPU allows; the Pentium III keeps its budget at Low. |
| SAV-D39 | The Afterglow dialog's shell | `/c` shows the Afterglow dialog (`dialog_v2.rs`, laid out by `template_v2.rs`) and falls back to the plain one for high contrast, 256 colours or fewer, a `PlainDialog` value of 1 in the saver's key, or a failure to create or set it up. Its controls keep the plain dialog's identifiers (the swatches take the palette field's `+1`, `+2`, and so on), so one reader and one writer serve both. The banner is the scene at Low detail rendered once at the control's pixel size at a placeholder moment, darkened towards the left; the preview is a `Saver` in preview mode at the pane's size on a 50 ms timer, rebuilt when the palette, light mode, seed, text or a scene setting changes. The swatches are subclassed for the arrow keys, which means the original button procedure is kept in the dialog's state: the images have no writable data section, so a `static` would fault. Group titles and the banner are owner-drawn statics | Assumed | Reusing the identifiers and the one `show` and `collect` keeps the fallback exactly as it was and costs no second reader. Rendering the banner once and drawing text over it with GDI means no bitmap is embedded. The banner moments are placeholders for WP-dialog-v2-art. |
| SAV-D40 | The Afterglow dialog's size | About 14 to 15 KiB per `.scr` at `opt-level = 3` (up to 19 KiB for the x86-64 cracktro) for the dialog glue and its imports (the layout, the drawing, the timer and the fallback test), more than the 8 to 14 KiB estimated at `-Os`; every file stays inside its budget with room to spare. The v1 dialog generator stays as the fallback | Assumed | The scene and the shell are already in every file, so only the glue is new. |
| SAV-D41 | Threads | The x86-64 build renders in bands of rows on a small pool of idle-priority worker threads (at most seven) when the machine has more than one processor; the core gains a `Bands` interface with a serial default, and the result is byte-identical with any number of bands. The Pentium III build stays single-threaded. Design in `docs/threads.md` | Assumed | At 1080p and full quality one core gives 12 to 54 fps; the brief asks for 30 on a modern machine. |
| SAV-D42 | Windowing for the Linux edition | `winit` 0.30 (features `rwh_06`, `x11`, `wayland`, `wayland-dlopen`; no client-side decorations) rather than SDL: it is pure Rust, so there is no C library to link, ship or find on the target machine, opens X11 and Wayland libraries only when run (one binary for both), hands wgpu its raw window and display handles directly, and can make a child of an existing X11 window (`with_embed_parent_window`) for xscreensaver. The binary is 6.5 MB stripped. Dependencies added: winit, cpal 0.17 (ALSA), x11rb 0.13 (already in winit's tree), and what they bring; `cargo deny` passes with no new licence exception | Assumed | SDL3 would add a shared library or a C build for no feature this program needs; winit is what wgpu is written against. Swap: the window code is `platforms/linux/src/app.rs` alone. |
| SAV-D43 | The Linux settings file and defaults | `$XDG_CONFIG_HOME/liminal-hq/afterglow-savers/twilight.toml` (`~/.config/…`): a flat `Name = value` subset of TOML with the Win32 registry names, parsed by hand (no TOML dependency), a choice writable by label, a bad line skipped and a bad value the field's default; flags over it. This edition defaults to `RenderScale` 100, `Detail` Ultra and a `FrameCap` of 60 (0 for vsync, or 10 to 240), which replaces `MaxFps` here; the other defaults, `Sound` on at `Volume` 28 included, are the Win32 ones. It supersedes the path `~/.config/afterglow-savers/twilight.toml` in `docs/gpu-twilight.md` | Assumed | The graphics card makes the Pentium's quality ladder free; the folder follows the other Liminal HQ programs. |
| SAV-D44 | Ending, and the hack | The saver ends on a key, a button, or more than 10 px of pointer movement measured from the first report after the window has settled (the reports in the first 0.5 s only set that place); closing the window ends any mode. A hack (`-window-id`, `-root`) ignores input and is silent unless `--sound`, because xscreensaver ends it and expects silence; it always uses X11. Fullscreen is the primary monitor, sized and placed explicitly as well as asked for, so it also covers the screen with no window manager. Only the primary monitor: **OWNER DECISION: one window on the primary monitor or one on each? Default: primary only. Swap: create a window per `event_loop.available_monitors()` in `start`** | Assumed | Matches SPEC section 4 and xscreensaver's contract; multi-monitor needs a surface and a renderer per display. |
| SAV-D45 | Sound on Linux | `savers_core::audio` at 48 kHz `f32` stereo through cpal's default ALSA device (PipeWire and PulseAudio answer to it), synthesized on its own thread with a second tiny Twilight scene for the cues, queued eight blocks ahead; the device's rate if it will not do 48 kHz. A gap fades the last frame over 20 ms, the end fades over 150 ms. No device, or one that will not open, is silence. `Sound` and `Volume` as the settings say; off in `--preview`, and off as a hack unless `--sound`. Headless, `--audio-wav` writes the score to a WAV | Assumed | docs/audio.md and SAV-D35, SAV-D38; no click is the rule for every edition. |
| SAV-D46 | Testing the Linux edition | `make check-gpu` runs the program on its own Xvfb with lavapipe, grabbing that server's framebuffer and sending keys and moves to that server only, with `WAYLAND_DISPLAY` cleared on every command and sound captured through ALSA's file plug-in; kept out of `make check` because it needs a display server and tools the gate does not, and skips with a note when one is missing. The window frame is held to the CPU frame's parity budget. Never run against the owner's session | Assumed | AGENTS.md: no host desktop capture or key injection. |
| SAV-D47 | The Collection's size guard | The Collection's `.scr` may be 448 KiB (the other five stay at 384 KiB, the five together at 1.5 MiB), because it links every scene and now every score; a single saver links only its own score (`screensaver_main!` takes a score maker beside the scene maker), 14 to 22 KiB more per file, the Collection 55 KiB more | Assumed | A `match` over every saver in `score_for` would put all six scores into every file (about 55 KiB each); naming the score in the program keeps the others out. The Collection needs them all. |
| SAV-D48 | Win32 sound path | `waveOut` in three buffers of about 300 ms, no thread: the frame loop refills finished buffers (`WHDR_DONE`) in 50 ms slices (a whole number of engine blocks, so cutting a render up changes nothing), at least one a frame, six when the queue is low, never more than 1.2 s ahead of real time (so a device that does not keep time cannot make the saver render faster than real time). A buffer after a gap opens on a short ramp. The score's cues come from a second scene at 32 by 18 with the saver's seed, at scene time = audio time times Speed. Exit is `waveOutReset` with no tail (the sound stops with the picture). `/p`, `/c` and a missing wave device are silent, with no error. The Detail ladder of SAV-D38 is kept: the device may refuse a rate, then 22,050 Hz. No test hook is built into the programs: Wine is tested through a virtual sink (`scripts/wine-audio.sh`) and the ReactOS guest through QEMU's WAV back end (`guest.py --audio`) | Assumed | The doc's design, made concrete. A hook that writes files would add imports to every shipped program for a test that a virtual sink does better. |
