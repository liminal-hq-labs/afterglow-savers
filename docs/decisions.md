# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Status is **Owner** when the owner decided it and **Assumed** when work proceeds on a recommended default until confirmed.

| # | Decision | Choice | Status | Why |
| --- | --- | --- | --- | --- |
| SAV-D1 | Savers and file names | Four savers (Maze, Cracktro, Twilight, Ink) and a Collection, named "Afterglow <Name>" by string 1; files in 8.3 form with no spaces: `AGMAZE.SCR`, `AGCRACK.SCR`, `AGTWILIT.SCR`, `AGINK.SCR`, `AGCOLLCT.SCR` | Owner (names), Assumed (files) | The Display applet runs `"<path> /p <hwnd>"` without quotes, and Windows 9x stores short names; 8.3 names work everywhere. |
| SAV-D2 | Rendering | A CPU software renderer drawing into a 32-bit DIB, shown with `StretchDIBits`; no OpenGL or Direct3D | Owner | ReactOS's OpenGL is poor, and a software renderer looks the same everywhere. |
| SAV-D3 | Memory | `savers-core` is `no_std` with `alloc`; the Win32 shell's global allocator is the process heap (`HeapAlloc`) | Assumed | Frame buffers and textures depend on the screen size; a heap keeps the scenes simple, and the process heap needs no C runtime. |
| SAV-D4 | Pentium floats | The i586 target uses the x87 FPU (the default 32-bit ABI) with MMX and SSE off; afterfetch's soft-float target is not used. x86-64 uses its SSE2 baseline | Assumed | A renderer is float-heavy outside its inner loops; soft-float would cost ten times more, and every Pentium has an FPU. |
| SAV-D5 | Maths | The core's own `sin`, `cos`, `sqrt`, `exp`, `pow` and value noise, deterministic, with a magic-number float-to-integer conversion; inner loops are 16.16 fixed point | Owner (no libm), Assumed (method) | No libm in `no_std`; x87 `fistp` with Rust's saturating casts is slow, and fixed point is fast on every target. |
| SAV-D6 | Determinism | The same seed, settings, size and time give the same frame on one build; the golden frame tests run on the host build only, because x87's extended precision may round a value differently | Assumed | Exact cross-FPU agreement would forbid floats; one-build determinism is what tests and previews need. |

| SAV-D51 | Bands in the core | `savers_core::bands`: a `Bands` trait (`run(rows, job)` over disjoint ranges that cover `0..rows`, in parallel or not; `Serial` is the default) that a platform gives a saver with `Saver::set_bands`, reaching every scene as `Ctx::bands` (the design's `render_bands` per scene became one field, so no scene needed a second entry point). The finishing chain (bright pass, one blur pass at a time over all planes, the packing, the glow overlay, the output pass) and the scenes' per-row and per-column loops go through it; `Shared` (a slice several bands write in disjoint parts, through `unsafe` methods that state the promise) and `rows` (a frame cut into `Rows` bands) are the only unsafe code in the core. A pass that reads a neighbour another band writes (Ink's aurora and relief) reads a copy of the frame taken before it. The frame is the same byte for byte with any bands, which `bands_do_not_change_a_byte` checks for every scene with 1, 2, 3 and 8 bands, run in reverse order and on threads; the goldens did not change. With one band the frame times stay within about 5% of the old serial ones (the bounds checks in `Shared`) | Assumed | The design in `docs/threads.md`; the serial cost is the price of one code path for both. |
| SAV-D52 | The x86-64 worker pool | `platforms/win32/src/pool.rs`: `GetSystemInfo` processors minus one workers, at most seven, made with `CreateThread` at idle priority, each waiting on its own auto-reset event; a pass is cut into four chunks per thread that the caller and the workers take from one counter, and the last worker to finish sets the `done` event. A pass that has waited 12 ms for a worker raises them to normal priority until it ends, so a busy machine can never freeze the frame behind an idle-priority thread. Only full-screen runs of a million pixels or more get a pool; the preview, the dialog and the Pentium build stay serial and import nothing new (`imports.allow` lists the six kernel32 calls with the tag `64`). A `Threads` registry value overrides the count (1 for none, 2 to 8 in all) and is deliberately not in the settings table or the dialog. `bandcheck.exe` (a test program, run by `scripts/smoke-wine.sh`) renders every scene with one thread and with eight through the real pool. **OWNER DECISION: a Threads slider in the dialog? Default: no, registry only. Swap: add `Key::Threads` to `settings.rs` and a row in the dialog, and read it in `saver.rs` instead of the registry value** | Assumed | The doc asks for no setting, a plain off switch costs nothing, and a dialog row would collide with the dialog art work.
